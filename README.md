# 파이썬 클린 아키텍처


## 좋은 설계란

코드의 의도를 명확히 파악할 수 있고, 유지보수가 용이하며 요구하는 비지니스 상황에 유연하게 대응할 수 있으면 좋은 설계가 될 수 있다고 생각합니다. 클릭 아키텍쳐는 이를 위한 유연하면서도 기본적인 룰이라고 할 수 있겠습니다.


## 코딩 AI 툴이 엄청난 능력을 내고 있는데, 클린 아키텍쳐가 필요할까

2025년부터 업무에 클로드를 적용해보며 엄청난 능력과 시간 단축의 이점을 경험할 수 있었습니다. 그러나 아직은 코딩 AI 툴은 사용자의 능력에 따라 나오는 결과물이 다르다고 생각합니다.
초기 데모 서비스에는 클린 아키텍쳐까지는 필요하지 않지만, 대중 서비스로 발전하는 과정에서는 협업, 비지니스 요구 대응에 필연적으로 필요하다고 생각하고, 클린 아키텍쳐를 공부하며 정리해보기로 했습니다. 

## 다루는 것

클린 아키텍쳐에 대한 개념은 심플하지만 어떻게 구현할지는 막막하기만 합니다.
요구사항 정의부터 FastAPI 배포까지, 클린 아키텍처의 4개 레이어를 샘플 프로젝트에 적용해보며 익숙해지는데 목표를 둡니다. 
저 역시 공부하며 정리하기 때문에 내용에 계속적인 변화가 있을 예정입니다.

- 비즈니스 규칙을 순수 Python 코드(Entities)로 표현하는 방법
- Use Case가 Entity를 조율하는 방식
- Repository 인터페이스로 DB 의존성을 역전시키는 DIP 원칙
- SQLAlchemy ORM 모델과 도메인 Entity를 분리하는 이유
- DB 없이 0.05초 만에 20개 테스트를 통과하는 테스트 전략

## 덧붙여
클린 아키텍쳐를 작은 프로젝트로 구현해보며 이해하고, 설명하는데 목표를 둡니다. 클로드와 함께 작업합니다.
