# 01. 클린 아키텍처란 무엇인가?

Robert C. Martin(엉클 밥)이 제안한 소프트웨어 설계 원칙으로, 비즈니스 로직을 프레임워크·DB·UI 같은 '세부 구현'으로부터 완전히 분리하는 것을 목표로 합니다. 
이로 인해 테스트와 변경을 용이하게 할 수 있습니다.
핵심 아이디어는  — **의존성은 항상 안쪽을 향해야 한다**는 것입니다.

구체적인 특성을 예로 들면 다음과 같습니다.
| 특성 | 설명 |
|---|---|
| **프레임워크 독립적** | FastAPI를 Flask로 바꿔도 비즈니스 로직은 그대로 |
| **DB 독립적** | SQLite에서 PostgreSQL로 바꿔도 domain 코드는 무영향 |
| **UI 독립적** | REST API든 CLI든 같은 Use Case를 재사용 가능 |
| **테스트 용이** | 서버·DB 없이 순수 Python 코드로 규칙 검증 |

```
        구현 세부사항 (바깥쪽)
   ┌─────────────────────────────┐
   │  Frameworks & Drivers       │
   │  ┌───────────────────────┐  │
   │  │  Interface Adapters   │  │
   │  │  ┌─────────────────┐  │  │
   │  │  │   Use Cases     │  │  │
   │  │  │  ┌───────────┐  │  │  │
   │  │  │  │ Entities  │  │  │  │
   │  │  │  └───────────┘  │  │  │
   │  │  └─────────────────┘  │  │
   │  └───────────────────────┘  │
   └─────────────────────────────┘
           비즈니스 규칙
   
   의존성은 항상 안쪽을 향합니다
```

 여기에서 좋은 설계란 무엇인가를 생각해봅니다. 코드의 의도를 명확히 파악할 수 있고, 유지보수가 용이하며 요구하는 비지니스 상황에 유연하게 대응할 수 있으면 좋은 설계가 될 수 있다고 생각합니다.
 클릭 아키텍쳐는 이를 위한 유연하면서도 기본적인 룰이라고 할 수 있겠습니다. 

 클린 아키텍쳐에 대한 개념은 심플하지만 어떻게 구현할지는 막막하기만 합니다. 그래서 샘플 프로젝트들을 구현해보며 익숙해지는데 목표를 둡니다.
